## 本轮范围

保留原品牌的白底 `#FFFFFF`、黑字 `#111111` 和亮橙 `#FF4F00`，重排页面层次，标题和正文采用系统字体。亮橙主要用于品牌标识、选中状态和大号数字；小字和来源链接使用黑灰文字，避免用亮橙承载需要阅读的小字。本轮不做整页换色、不做逐页字体裁剪，也不切换现有外部发布环境的运行时。仓库继续兼容 `package.json` 声明的 Node.js `>=20`。

首页与当期页缩小日期的视觉占比，主位展示本期主线标题和 `summary` 正文，随后呈现“六件事”、关键数字和完整条目列表。桌面侧栏提供目录；每条新闻使用原生 `details` 组织正文。设计样例使用 15 条新闻，实际条数由当期 JSON 决定。原 `invest` 内容以“产业观察”栏目呈现，两种阅读模式均保留，不新增正文没有的判断或数字。

2026-10-29 这一期的顶层 `headline` 和 `summary` 采用用户已确认预览稿的主线与导语。本轮内容变更限于这两项；其余 219 条新闻正文与 380 个来源 URL 保留，不因版式重构改写。

既有地图、往期与搜索功能保留，原 `/YYYY-MM-DD/`、`#full`、`#nXX` 等地址继续作为兼容目标。地图、归档页和关闭 JavaScript 后的阅读能力需要在本轮重新验收，不能引用旧版通过结果。

`defense-brief-v2-review` 中的静态预览用于确认设计，不是正式发布源。不要将整个预览目录覆盖到 `main`，也不要直接修改生成的 HTML 来维护每日内容。

## 编辑每天需要维护什么

每日简报的单一内容源仍为 `content/YYYY-MM-DD.json`。文件名与 `date` 必须一致，结构以 `data/schema.json` 为准。模板、CSS、浏览器脚本与简报正文分别维护，构建结果由同一套模板生成。

新增的顶层 `headline` 是可选的本期主线标题，最多 64 字，只概括本期正文已有事实。它与 `sections[].items[].headline` 的单条新闻标题不同。例如：

```json
{
  "date": "2026-10-29",
  "headline": "本期主线标题",
  "summary": "用一段话说明本期主线，内容必须来自本期正文。"
}
```

上面仅展示相关字段，不是完整可构建样例。完整结构参考仓库内已有一期 JSON。

未填顶层 `headline` 时，依次使用第一条 `highlights` 引用的条目标题、首条新闻标题；旧简报无需为适配本轮版式逐期补写主线标题。`summary` 建议写成简短一段主线摘要，只概括本期正文已有事实，不为首屏补充新事实；它在首屏正文显示，也继续用于分享描述和 RSS。`invest` 字段名保持不变，页面显示为“产业观察”，一分钟版和完整版均可阅读。

正文、来源、领域和位置仍需编辑核对；版式调整不会自动补齐缺失事实。不要为填满卡片或地图编造字段。条目顺序改变后，复核 `highlights.item`、`stats.item`、`featured` 和 `related` 的引用编号。

首次使用或依赖锁定文件有变化时安装依赖，然后构建与检查：

```bash
npm ci
npm run build
npm test
npm run verify
npm run preview
```

在 <http://127.0.0.1:4173/> 检查首页、当期条目、往期、地图和来源链接。预览服务器按 `site.config.json` 的 `baseUrl` 路径模拟部署前缀；当前 `https://dibao.news/` 的前缀为空，只有配置为子路径部署时才使用对应的 `/defense-brief/` 等前缀。以终端打印的地址为准。`preview` 持续运行，按 `Ctrl+C` 退出。构建成功后，必须将 JSON 与重新生成的页面、CSS、JS、RSS、sitemap 等实际变更一起纳入提交；GitHub Pages 当前从 `main` 根目录发布，不会代替编辑运行构建。

## 如何回退并保留后续简报

如果上线后需回退样式和模板，先暂停有冲突的每日发布写入，在最新 `main` 上新建回退分支。针对本次合并提交执行 `git revert`，再使用保留下来的最新 `content/` 重新构建并检查，通过 Pull Request 合并回 `main`。不要把旧目录整体覆盖回来，也不要用 `git reset` 或强制推送回退仓库；这些做法可能丢掉上线后新增的简报。

如果本次 PR 以普通 merge commit 合并，命令形式为 `git revert -m 1 <本次合并提交>`；如果采用 squash，使用 `git revert <本次 squash 提交>`。必须以真实合并记录确定目标，不要照抄占位符。若回退遇到内容或生成文件冲突，保留后续新增或修正的 JSON，以回退后的模板重新生成页面，再运行 `npm run build`、`npm test`、`npm run verify`。确认 GitHub Pages 完成这次回退部署后，恢复每日发布流程并复核它已同步最新 `main`。
