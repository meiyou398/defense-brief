# Implementation contract

Plain Node ESM templates compatible with Node >=20, one CSS and one deferred browser JS. All content is in HTML. No JS defaults to full text, all map feed rows, all archive entries. JS adds `document.documentElement.classList.add('js')` only after successful setup. No fetch, client templates, or content generation. CSS must not hide full text unless `.js` is present.

## Page layout and classes

`body.v2-brand[data-page=issue|map|archive|about|sources|subscribe|404]`. The shared header keeps existing hooks and adds the brand layout classes: `.site-header.b-header`, `.header-inner.b-container.b-header-inner`, `.brand.b-brand`, `.brand-mark.b-brand-mark`, `.site-nav.b-nav`, `.b-brand-note`, `.b-search`. Navigation links use `aria-current`; the map page adds `.b-edition.b-container` with a link back to its issue. Shared footer: `.b-footer .b-container .b-footer-inner`, `.b-brand`, footer navigation. All pages use the system sans font stack; headings, body text and numbers do not request Google Fonts or another remote font stylesheet.

Issue pages use `main#main.b-container`. `.b-edition` displays a compact date, weekday, issue number and cutoff time; `.b-issue-nav.issue-nav` links dated issues. `.b-hero .b-hero-copy .b-kicker`, `h1#headline`, `.b-intro`, `.b-coverage`, `.b-hero-actions`, `.b-read-link`, `.b-secondary-link`, `.b-mode-toggle.mode-toggle`; `.b-hero-guide` contains the overview links. The main title comes from the optional issue-level `headline`, then the first highlight's referenced item title, then the first item title. `summary` appears as `.b-intro` in the HTML body. The date is supporting text rather than the old giant date block.

Highlights: `section#highlights.b-highlights`, `.b-section-heading`, `.b-highlight-grid`, `.b-highlight-main`, `.b-highlight-number`, `.b-highlight-text`, `.b-highlight-arrow`, `.b-highlight-source`. Stats: `.b-stats .b-small-heading .b-stat-grid .b-stat .b-stat-number .b-stat-label .b-stat-reference`; each stat links to its full item. No stats are rendered when the data is absent.

Full reading: `.b-reading-layout`, `.b-main-column`, `section#full.b-full[data-full-only]`, `.b-reading-note`, `.b-news-group`, `.b-group-heading`, `h2[id=theater-*]`. Each `details.b-story[open]` has a native `summary`, `.b-story-number`, `h3`, `.b-disclosure`; its `.b-story-body[id=nXX][data-item-card][tabindex=-1]` contains `.b-prose`, optional `.b-analysis`/`.b-caution`, `.b-sources`, `.b-evidence` and `.b-related`. Item IDs are unique. Optional `section#industry.b-industry` is a sibling of the full section, uses the existing `invest` content and the label “产业观察”, and remains visible in brief and full modes. Desktop sidebar: `.b-reading-sidebar[data-full-only] .b-sticky details.b-contents[open]`, directory links, `.b-map-entry`, `.b-top-link`. The reading layout itself has no `[data-full-only]` attribute. The homepage links to the dedicated issue map; it no longer embeds the old map preview or separate featured cards.

Brand colors are white `#FFFFFF`, black `#111111`, bright orange `#FF4F00`; orange is reserved mainly for brand marks, selected states and large numbers. Sources and small text use black/gray. Reading content and sidebar share a desktop grid with a main column capped at 760px. On mobile the header navigation wraps, highlights become one column, stats wrap into a two-column grid, and the contents move above the full text; the large hero guide is hidden. `.wrap` and `.wrap-map` remain available to map and informational layouts. Existing `.prose`, `.archive-search`, `.archive-month`, `.archive-list`, `.archive-row`, `.archive-date`, `.archive-copy`, `.tier.tier--1|2|3|4` and map selectors retain their contracts below.

## Reading mode / anchor contract

`[data-mode-button=brief|full]` buttons in `.b-mode-toggle` use aria-pressed. `[data-full-only]` marks only the full news section and reading sidebar; highlights, available stats and industry observations remain visible in both modes. The current issue template has no `[data-brief-only]` map/featured wrapper. Mode is stored at `defense-brief:mode` (try/catch). `needsFull(hash)` returns true for `#full`, item hashes and any resolved fragment target within `[data-full-only]`; therefore `#theater-ID` directory links force full mode even when brief mode is saved. Same-page clicks, initial restoration, hashchange and popstate apply this rule and scroll to the resolved target. Fragment links work without JS because all story disclosures are initially open. The unique item target is `.b-story-body[id=n01][data-item-card]` inside its `details.b-story`, rather than a duplicated featured card. Click same-page #nXX => full, open its enclosing details, focus the item target, then scroll/highlight `.is-target` for2sec; reduced motion respected. Change modes preserves scrollY and updates the fragment through History API; selecting brief clears a fragment that requires full mode. `#industry` remains usable in either mode because its section is outside `[data-full-only]`. On no JS mode controls are hidden, full reading stays visible, and native details can still be collapsed or expanded by the reader.

## Map contract

Each `[data-map]` has `data-default-item` (first highlight with coordinate), `data-preview=true|false`, and its own selection state. `[data-map-stage]` positioned `aspect-ratio:900/640`; `[data-map-canvas]` contains image and markers and scales as one using CSS `transform` / `transform-origin`. `[data-map-image]` role img and aria-label, interactive siblings outside roleimg. `[data-marker][data-item=1][data-theater=europe][data-domain=sea]` real buttons, ordered numerically, position via inline left/top %. Marker class `.map-marker.tier--N`. Visual spans allow 16px mobile glyph while hit area >=44px; implement CSS carefully for dense markers. `[data-popup][data-item]` static per-item content, outside transformed canvas, inline left/top %, class `.map-popup`; JS toggles hidden. Anchor inside popup points to issue #nXX. All popups initially hidden. Desktop popup flips with `.is-left`, stays within stage (JS can clamp). Mobile popups never show.

`[data-feed-row][data-item][data-theater][data-domain]` are `li.map-feed-row`, with anchor `[data-select-item][data-item]` href to full text (progressive fallback). `.map-feed .map-feed-list` list; fixed520px map page, preview approx6rows desktop. `[data-mobile-detail]` contains one pre-rendered `[data-mobile-item][data-item]` per item hidden until selected, shown below map mobile only. Selected marker/row/offmap button `.is-selected`, aria-pressed for buttons, aria-current on feed anchor. Filtered markers `.is-filtered` opacity.25 and disabled; filtered rows `hidden`. `[data-offmap]` groups in stage lowerleft with `[data-offmap-item][data-item][data-theater][data-domain]` buttons. Offmap selection shows row and mobile detail, no popup. Escape/map background click closes popup/selection. Do not intercept popup link clicks.

`[data-filter-group=theater|domain]` contains `[data-filter][data-filter-key=theater|domain][data-filter-value=...]`, aria-pressed. theater all has empty value. Within each map root `[data-empty]` initially hidden with `[data-clear-filters]`. Query `theater`, `domain`, intersect single choices, click same toggles off. Invalid values ignored; history replace on changes, handle popstate. Counts initial total. No tier UI first release. Discard selected item if excluded, prefer first visible located item then first item. On load default #01 sample. `[data-zoom=in|out]` zoom1,1.5,2 around selected marker and back1 resets, controls have aria-label and disabled bounds. Map click background closes selection only when not marker/popup/offmap/zoom.

## Archive contract

`[data-archive-search]` search input, `[data-archive-row]` each row `data-search` normalized complete content (summary, all item fields/source notes, invest). `[data-archive-month]` groups hide if no visible rows. `[data-search-status]` aria-live count; `[data-search-empty]` initially hidden. `?q=` initial URL and history replace; whitespace-separated terms AND, case-insensitive Unicode-normalized. All issue rows/links prebuilt. Search is client-only filtering of rendered rows, never fetch or client rendering.

## Budgets / a11y

app.js raw <=15KB target (therefore gzip <=15KB), built-in-only verification. CSS tokens preserve the original white/black/orange brand, no shadow/gradient/corners (clock circle allowed); marker selection ring via outline. Visible keyboard focus, no body horizontal overflow390px; scroll only intended local strips. Keyboard button enter/space native; tab markers numerical. Fonts use the local system sans stack for all pages; no external font link, preconnect or per-page font subset. Title/h1/description/canonical/OG/RSS per page. Relative internal href/src; absolute URLs only metadata, XML link locations and external sources.
